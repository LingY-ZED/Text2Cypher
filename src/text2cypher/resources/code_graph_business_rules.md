# 代码知识图谱业务语义

以下规则用于理解代码知识图谱的业务含义。只在当前 Schema 中存在对应标签、关系、属性和枚举值，且用户问题确有相关意图时使用；不得因本说明虚构图结构。

## 锚点与归属

- `方法`、`类`、`微服务`的归属链为：方法 → 类 → 微服务。由方法寻找所属服务时必须沿这条链，不能从目标 API、交换机或队列的归属反推调用方服务。
- 完整包名的方法使用 `方法.全限定名` 精确定位；`Class.method` 用方法名和所属类的简名共同定位；只给出方法名时匹配所有同名方法，并返回目标方法的全限定名，不猜测唯一实现。
- 类归属只用于定位或过滤。后续调用关系必须重新从方法节点出发，不能把类节点接入方法调用路径。

## 本地调用、入口与 REST

- `方法-[:调用]->方法` 表示调用者指向被调用者：上游逆向、下游正向。直接或下一跳只查一跳；调用链、链路或路径最多展开五跳，并保留方法顺序。
- 上游入口由可反向到达目标方法的入口方法，经 `调用类型='接口入口'` 指向 `API类型='上游API'` 获得。完整上游链返回目标方法、入口 API 和有序方法路径。
- REST 出口由调用方法经 `调用类型='远程调用'` 指向 `API类型='下游API'` 获得；目标服务取下游 API 的 `目标微服务`。关系类型和 API 类型必须同时过滤。
- 跨服务边界由下游 API 经 `调用类型='跨服务调用'` 指向目标上游 API，再进入目标入口方法。默认只展开一个直接边界；映射缺失时保留已确认的本地调用链和下游 API，不得过滤全部结果。
- 完整下游链返回目标方法、有序方法路径、远程下游 API 和目标服务；有目标上游 API 或入口方法时可一并返回。远程出口是完整链的必要部分，跨服务映射才是可选扩展。

## MQ 与服务级关系

- 完整消息路径固定为：发布方法 -[消息流类型=发布]-> 交换机 -[消息流类型=路由]-> 队列 -[消息流类型=消费]-> 消费方法。发送服务取发布方法的归属链，接收服务取消费方法的归属链。
- 队列名称只能绑定队列自身的名称属性，不能当作服务名；不得用交换机或队列的归属代替发布方、消费方服务。
- 若问题只问某队列的消费者，只查询队列到消费方法的消费边，不额外引入发布方或交换机。若问服务间 MQ 依赖，使用服务间依赖关系，不从完整消息路径推导无关服务集合。
- 查询已绑定服务的公开 API 等服务级资源时，资源必须经自身完整归属路径回到该服务；接口实现关系的起点是实现类，返回实现类而不是被实现接口。

## 影响、结果与拆分

- 方法变更影响分析中，全部上游方法使用反向调用链；入口 API 使用可反向到达变更方法的入口方法；直接远程下游从变更方法出发，目标服务字段名为 `下游服务`，不能泛化为外部服务或外部对象。
- 同一调用链或消息路径中的方法、API、服务、交换机、队列属于同一逐行对应的事实，不能拆成无法恢复配对的独立结果。固定锚点上的独立统计、明细或依赖集合可以各自重复锚点并独立计算。
- 非聚合实体或路径结果在最终完整投影使用 `RETURN DISTINCT`；`WITH DISTINCT` 不能替代最终去重。聚合必须保留题目要求的分组维度。
