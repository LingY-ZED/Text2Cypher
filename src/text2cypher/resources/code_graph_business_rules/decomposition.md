# 代码知识图谱业务语义：问题拆分

- 只要同一道方法变更题同时要求“全部上游方法”“可达入口 API”“变更方法直接 REST 下游”这三个集合，无论是否出现“分别”二字，都必须拆成三个独立且重复方法锚点的子问题；禁止合并为一个 Cypher。
- `full_method_call_chain`：方法或入口 API 的完整调用链保留单个查询，由确定性工具展开服务内、REST 和 MQ 链路，保留原始锚点与显式限定。
- 方法变更语境中的泛称“外部服务”固定解释为该变更方法通过 `下游调用→目标服务` 直接访问的下游服务，不是通过 `调用` 关系找到的上游调用方所属服务；对应子问题必须写明“变更方法直接远程调用的下游服务”。
