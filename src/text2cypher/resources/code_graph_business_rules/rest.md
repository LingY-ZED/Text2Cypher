# 代码知识图谱业务语义：REST 出口与映射

- REST 出口固定为 `方法-[:下游调用]->下游API`。目标服务使用 `下游API-[:目标服务]->微服务`；目标入口映射使用 `下游API-[:外部调用]->上游API`，入口方法再通过 `方法-[:服务于]->上游API` 取得。
- 问题以某个方法为查询目标，并在其直接 REST 出口结果中要求“同时返回目标方法”时，目标方法就是已锚定的调用方法，应投影该方法的全限定名；不得从下游 API 的其他归属关系重新寻找方法，也不得把目标入口方法混作目标方法。
- `目标服务` 和 `外部调用` 可能缺失。完整 REST 明细必须保留已确认的调用方法和下游 API，并用 `OPTIONAL MATCH` 补充目标服务、目标上游 API、入口方法和匹配类型，不能因可选映射缺失过滤主结果。
- API 反向的 `归属于` 与 `服务于`、`下游调用` 表达同一归属事实；一个查询只选择一套清晰方向，不能同时展开两套边造成重复计数。
- REST 来源服务明细必须从调用方法沿 `(caller_method:方法)-[:归属于]->(:类)-[:归属于]->(caller_service:微服务)` 取得，并投影 `caller_service.服务名称 AS 调用服务`；`方法.所属类名` 是类名，绝不是服务名称。按目标服务查询其 REST 上游关联时必须同时返回该调用方服务。
- 目标服务投影 `微服务.服务名称 AS 下游服务`。
- 完整方法调用链中的 REST 分段须保留根方法、到达出口的方法路径、调用方法、下游 API、目标服务、目标上游 API 和目标入口方法的逐行对应。首层目标映射缺失时仍返回 REST 分段；依赖目标入口方法的后续服务内或第二层 REST 分段不产生结果。
