# 代码知识图谱业务语义：有序路径与完整链

- 有序普通方法路径使用 `链中下一节点`。同一路径中的每条关系必须具有相同 `路径签名`，相邻关系的 `位置索引` 必须连续；最终用 `nodes(path)` 投影有序方法列表。
- 完整入口链可以是目标方法自身、一次 `接口调用`、一段 `链中下一节点`，或先一次 `接口调用` 再接有序普通路径。可以在同一变长路径中匹配 `接口调用|链中下一节点`，但必须约束 `接口调用` 至多出现一次且只能位于首跳，并只对其中的 `链中下一节点` 校验相同 `路径签名` 和连续 `位置索引`；不得用方向不明的 `OPTIONAL MATCH` 和 `CASE` 拼接伪路径。
- 完整下游链可用从目标方法开始的 `链中下一节点*0..` 同时覆盖“目标方法直接 REST 出口”和“沿有序路径到达 REST 出口”，并完整投影 `目标方法`、`方法路径`、`下游API`、`下游服务`、`目标上游API`、`目标入口方法`。非空有序路径仍须校验路径签名和位置连续性；`目标服务`、`外部调用` 与目标入口使用 `OPTIONAL MATCH`，不得因映射缺失删除主结果，也不得把目标方法误命名为入口方法。
- 完整方法调用链拆分后的每条查询都从相同原始锚点重新匹配。服务内查询返回最多十跳的有序方法列表；REST 和 MQ 查询也必须携带到达出口或发布方法的有序方法列表。只返回属性和列表，不能返回节点或 Path。每个 `接口调用|链中下一节点` 路径继续遵守接口调用首跳、路径签名和位置连续性约束。
